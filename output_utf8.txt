0. Migration Overview & Goals
The current system is a functional but shallow prototype that relies primarily on third-party blacklists (PhishTank), simple heuristic keyword matching, and a SQLite cache. Its detection logic collapses on zero-day phishing domains that have not yet been indexed by external APIs, and its scoring is deterministic threshold-based rather than mathematically derived.

The TGIS framework replaces this with a self-contained, mathematically rigorous detection engine. Instead of asking 'Is this URL on a known bad list?', the system asks: 'Does this domain's infrastructure graph match the temporal growth pattern of a legitimate domain?'

1. Stage 0 — URL Preprocessing Upgrade
PROMPT THIS SECTION FIRST. It establishes the canonical domain extraction that all subsequent stages depend on.

1.1 Master Prompt: Preprocessing Service Rewrite

Rewrite app/services/preprocessing.py to implement the following pipeline, strictly in this order. Replace the existing normalize() function with a new function called extract_candidate_domain(raw_url: str) -> CandidateDomain that returns a dataclass.

Step 1 — RFC 3986 URI Decomposition: Parse the raw string using Python’s urllib.parse.urlsplit(). Do not use regex. Extract scheme, netloc (authority), path, query, and fragment into separate named fields.

Step 2 — Percent-Decoding: Apply urllib.parse.unquote() to the netloc and path components to resolve hex-encoded obfuscation such as %61%64%6D%69%6E.

Step 3 — Canonicalization: Lowercase the scheme and authority. Strip the default ports (remove :80 for http and :443 for https). Resolve relative path traversals using posixpath.normpath() on the path component.

Step 4 — IDN Punycode Conversion: For the authority component, apply the ToASCII algorithm via Python’s built-in .encode('idna').decode('ascii') on each label of the domain. This converts spoofed Unicode domains (e.g., Cyrillic lookalikes) to their true xn-- Punycode form before any further analysis. Wrap in try/except UnicodeError and fall back to the raw label if encoding fails.

Step 5 — Candidate Domain ($d$) Extraction: Use the tldextract library with the update_now=False, include_psl_private_domains=True flags to parse the FQDN. Extract the eTLD+1 (registered_domain). This is the Candidate Domain $d$. If registered_domain is empty or None, raise a ValueError with message 'Cannot extract valid candidate domain from input'.

Step 6 — State Initialization: Record the current POSIX timestamp using time.time() as the Temporal Anchor $t$. Return the following dataclass:
@dataclass
class CandidateDomain:
    raw_url: str
    candidate_domain: str   # $d$ - the eTLD+1
    fqdn: str               # full decoded authority
    subdomain: str
    scheme: str
    temporal_anchor: float  # $t$ - POSIX timestamp
    is_ip: bool             # True if netloc is an IPv4/IPv6 literal
    punycode_converted: bool  # True if IDN conversion was applied

Tests to write alongside this: (1) A URL with %61%64%6D%69%6E in the path decodes correctly. (2) A Cyrillic spoofed domain converts to valid Punycode. (3) A bare IP address sets is_ip=True and candidate_domain equals the IP string. (4) A URL with :443 in the netloc has the port stripped. (5) A relative traversal path /../admin normalizes to /admin.

Never raise an exception from build_graph() itself; always return the best available graph.

3. Stage 2 — Expected Graph Density (EGD) Model
This stage implements the core mathematical innovation of TGIS: age-normalized baselining. It replaces the old threshold-based scoring entirely.

3.1 The Problem Being Solved
Classical graph-based detection uses absolute density thresholds (e.g., 'fewer than 5 edges = suspicious'). This produces massive False Positive rates for Newly Registered Legitimate Domains (NRLDs), which have low edge counts simply because they are new. The EGD model fixes this by asking: 'How many edges should a domain of this exact age have?'

3.2 The Piecewise Exponential Function
For each edge type $k$ (infrastructure, certificate, ownership, routing), the system computes a separate expected edge count using the following saturation growth model:

E_k(a) = alpha_k * (1 - exp(-beta_k * a)) + gamma_k

Where:
  a         = domain age in days (float)
  alpha_k   = saturation ceiling for edge type k (learned from training corpus)
  beta_k    = growth rate constant for edge type k
  gamma_k   = baseline floor (minimum expected edges even at a=0)

4. Stage 3 & 4 — TIS Score + Sibling Contamination

4.1 Temporal Isolation Score (TIS) — Stage 3
The TIS score measures how anomalously isolated the candidate domain is compared to its age-normalized expectation. A domain with zero infrastructure edges when it 'should' have 10 scores very high on isolation.

Per-type isolation component (Equation 2):
  I_k(d,t) = max(0, E_k(age) - |E_k_observed|) / E_k(age)

If E_k(age) == 0: I_k = 0 (no expectation, no penalty)

Composite TIS (Equation 3):
  TIS(d,t) = SUM_k [ w_k * I_k(d,t) ]

Default weights w_k (from logistic regression on training corpus):
  w_infrastructure = 0.40
  w_certificate    = 0.25
  w_ownership      = 0.20
  w_routing        = 0.15

TIS is always in range [0.0, 1.0]. 1.0 = maximally isolated.

4.3 Sibling Contamination Propagation (SCP) — Stage 4
SCP is only activated when domain_age_days < 1.0 (under 24 hours old). For older domains, SCP score defaults to 0.0 and the final aggregation relies solely on TIS.

Sibling identification: Find all nodes s in G(d,t) such that s shares
  >= 2 infrastructure edge types with candidate domain d.

Jaccard similarity (shared infrastructure overlap):
  J(d, s) = |N(d) intersect N(s)| / |N(d) union N(s)|
  where N(x) = set of all neighbor node IDs of x in the graph.

Contamination weight (Equation 4):
  w_s = J(d, s) * (M(s) + 0.5 * TIS(s))
  where M(s) = 1.0 if s is a known malicious domain, else 0.0
  TIS(s) is the TIS score computed recursively for sibling s
  (NOTE: compute sibling TIS at depth=1 only, do not recurse further)

SCP score (Equation 5):
  SCP(d) = min(1.0, SUM_s [ w_s ] / normalization_factor)
  normalization_factor = max(1, len(siblings))

5. Stage 5 — Final Score Aggregation & New Response Schema

5.1 The TGIS Aggregation Equation
TGIS_final = alpha * TIS + beta * SCP + gamma * R

Where:
  alpha = 0.55  (TIS weight - primary signal)
  beta  = 0.30  (SCP weight - sibling contamination)
  gamma = 0.15  (R = residual heuristic signal, see below)

R (Residual Heuristic) - retained from old heuristic engine but
  downgraded to a tertiary signal. Compute as before (typosquatting,
  IP-based URL, long URL, excessive subdomains) but normalize to [0,1].

Verdict classification:
  TGIS_final < 0.30  -> SAFE
  0.30 <= TGIS < 0.60 -> SUSPICIOUS
  TGIS_final >= 0.60  -> MALICIOUS

Override: If local blacklist hit -> MALICIOUS (score = 1.0) immediately,
  skip all pipeline stages (existing behavior preserved for speed).
